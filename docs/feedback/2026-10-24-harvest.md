# `apply` — 1

## `unsupported-host:transcript-api-request-blob-rows`

- **BTC-Gateway** — 1 occurrence, 2026-10-23T22:09Z, notion-dev 0.45.2, Claude Code 2.1.306.

**Entry.** Kind `failed`. Where: `/notion-dev:ticket` → lean intake → `runtime.py
capture-ticket` → `host_capture.exchange()`. Claude Code 2.1.306 writes an additional
`"type": "api-request-blob"` row carrying each `tool_use` / `tool_result` with the same call
id; `exchange()` requires `row.type == message.role` and raised "unsupported host tool record
role" on the first such row. Effect: schema-5 capture impossible on that host; the run stopped
at intake and the user ran the ticket flow by hand without the runtime.

**Cause, re-derived rather than inherited.** Confirmed against a live 2.1.309 transcript on
WSL 2 Ubuntu: the host writes one `api-request-blob` row per distinct request message — `type`
`api-request-blob`, a `sessionId`, a content `hash`, and a `message` whose `role` is
`assistant` for the `tool_use` copy and `user` for the `tool_result` copy — with **no
`timestamp` and no `uuid`**. The result's copy lands *before* its canonical `user` row. The
old `exchange()` matched any row whose `message.content` carried the call id, so it reached
the mirror and failed the type-equals-role guard. Run unchanged against that live transcript,
the 0.45.2 code fails with the client's exact message; the fixed code selects the canonical
rows. The other transcript readers in the file (`_matching_calls`, `user_approval`) already
filter on `type`, so `exchange()` was the only reader affected.

**Disposition: `apply`.** Real, plugin-owned, and it blocks every lean run on current hosts:
`exchange()` now reads only `user`/`assistant` rows as conversation records. Skipping any
other row type can only fail closed: call and result must both still come from canonical rows,
so a mirror alone yields "completed tool exchange not in host transcript yet", never a
receipt. The type-equals-role guard is kept for canonical rows. The fix is plain Python with no
platform-specific behaviour, and runs in CI on both `ubuntu-latest` and `windows-latest`.

**Change.** `plugins/notion-dev/scripts/host_capture.py:134` (the row filter);
regression `test_host_request_mirror_rows_are_not_exchange_records` in
`scripts/tests/test_boundaries.py:126`. That test covers the live row order, a mirror whose
content differs from the canonical record, mirrors alone, and the kept role guard. Two
mutations went red: removing the filter, and turning the role guard into a skip.
